# 端到端用户场景

状态：M0 草案。场景用于验证需求完整性，不代表 UI、Agent 或技术实现。

## UC-01：建立可复核的个人基线

### 触发

用户希望改善某一领域，但现有资料分散、结论相互矛盾或已经过期。

### 主流程

1. 用户说明目标、背景和当前约束；
2. 系统列出完成基线所需的最少输入，并说明用途；
3. 用户提供文字、照片、测量或历史记录；
4. 系统分别记录用户陈述、观察事实和推断；
5. 系统标注日期、来源、质量限制、置信度与待确认项；
6. 用户确认、修正、拒绝或暂缓结论；
7. 系统生成一个带版本的当前基线。

### 异常与边界

- 输入质量不足时不得生成高置信度结论；
- D3 数据只按已说明用途处理；
- 用户拒绝某项推断后，旧推断不得继续作为当前事实；
- 涉及医学判断时只表达风险与就医边界，不进行诊断。

### 覆盖需求

`SYS-001`、`SYS-003`、`SYS-005`、`APP-001`、`APP-005`、`APP-006`、`APP-007`、`NFR-001`、`NFR-002`

## UC-02：从目标生成可解释的机会排序

### 触发

用户已有基线，希望知道“先做什么、为什么”。

### 主流程

1. 用户描述目标结果和时间范围；
2. 系统确认预算、时间、健康、审美偏好和不可接受项；
3. 系统生成候选改善机会；
4. 每个机会标注影响、成本、周期、风险、可逆性、依据和未知项；
5. 系统识别机会之间的依赖与冲突；
6. 用户调整权重或否定不符合偏好的机会；
7. 系统输出经过用户校准的优先级。

### 异常与边界

- 不以单一审美标准定义缺陷；
- 缺少证据的机会必须降级为实验或待验证假设；
- 高风险或不可逆项目不得直接进入自动执行。

### 覆盖需求

`SYS-002`、`SYS-003`、`SYS-004`、`SYS-006`、`SYS-008`、`APP-002`、`APP-003`、`APP-005`、`NFR-001`

## UC-03：执行一个有限周期的改善计划

### 触发

用户接受一组已排序的机会，希望把建议转成真实行动。

### 主流程

1. 系统将机会拆解为有限周期计划；
2. 每项任务包含频率、完成条件、成本、依赖和停止条件；
3. 用户确认计划和必要的外部动作；
4. 系统记录完成、跳过、困难、不良反应和临时调整；
5. 计划偏离时，系统根据真实反馈调整后续任务；
6. 周期结束后进入复盘，而不是自动无限延长。

### 异常与边界

- 系统不能伪造任务完成记录；
- 不良反应、风险上升或约束变化应触发暂停；
- 购买、预约、发送信息等对外行动必须获得动作级授权。

### 覆盖需求

`SYS-002`、`SYS-004`、`SYS-007`、`SYS-008`、`APP-004`、`NFR-002`

## UC-04：复盘结果并修订个人模型

### 触发

一个计划周期结束、用户主动要求复盘，或关键状态发生变化。

### 主流程

1. 系统汇总计划、完成记录、成本、主观体验和可观察结果；
2. 将结果与初始目标和基线比较；
3. 区分有效、无效、不确定和因执行不足无法判断的部分；
4. 用户确认或纠正复盘结论；
5. 系统更新相关状态、偏好、约束和建议权重；
6. 系统记录本次修订的理由并标记旧结论的状态；
7. 用户选择结束、延续或设计下一轮实验。

### 覆盖需求

`SYS-001`、`SYS-002`、`SYS-007`、`APP-006`、`NFR-001`、`NFR-002`

## UC-05：处理跨领域冲突

### 触发

两个以上领域的计划竞争相同的时间、预算、恢复能力或风险额度。

### 示例

- 增肌饮食与短期外形目标冲突；
- 护肤或医美恢复期与社交活动冲突；
- 工作强度、睡眠恢复与训练计划冲突；
- 社交流量扩展与预算、时间配置冲突。

### 主流程

1. 系统识别共享资源和互斥约束；
2. 说明冲突来自哪些事实、计划和假设；
3. 给出延后、降级、替代或重新排序选项；
4. 用户选择权衡原则；
5. 系统同步更新受影响计划，并保留决策原因。

### 覆盖需求

`SYS-002`、`SYS-003`、`SYS-006`、`SYS-007`、`NFR-001`、`NFR-002`

## 场景完整性检查

任何 MVP 候选至少回答：

- 从哪里获得可复核的基线？
- 目标和约束如何进入排序？
- 建议如何转化为有限周期行动？
- 真实执行和异常如何被记录？
- 结果如何改变下一次决策？
- 用户如何纠错、撤销和删除？
