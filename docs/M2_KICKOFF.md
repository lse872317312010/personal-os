# M2 启动输入

状态：ready for architecture decisions

## M2 要回答的问题

1. 客户端形态：移动、桌面、Web 及其优先级；
2. local-first、cloud-first 或 hybrid 的数据权威边界；
3. 事件存储、对象投影、全文/语义检索和 Blob 的职责分离；
4. 单设备到多设备的同步、冲突和离线行为；
5. D2/D3 加密、密钥管理、备份与删除传播；
6. 模型调用、本地模型、云端模型和敏感度路由；
7. Agent 权限、工具调用、人工确认与审计执行面；
8. Schema/事件迁移、可观测性和契约测试实现；
9. 成本、延迟、可维护性、供应商锁定和未来商业化路径。

## 决策顺序

1. 明确首个 dogfooding 设备与交互场景；
2. 决定数据权威位置和 D3 边界；
3. 定义逻辑组件与信任边界；
4. 比较存储、同步、模型和客户端候选方案；
5. 用 M1 事件序列做架构走查；
6. 记录 ADR 后再冻结具体技术。

## 每个候选方案必须提交

- 满足/违反的 M0/M1 条款；
- 数据流和信任边界；
- 离线、同步、冲突、删除和恢复行为；
- 安全与隐私风险；
- 开发复杂度、运行成本和维护负担；
- 供应商退出与数据迁移方式；
- MVP 最短实现路径和未来扩展代价。

## 当前禁止直接决定

在没有上述对比前，不直接选择 Flutter、Rust、数据库、事件框架、向量库、云厂商或模型供应商。
