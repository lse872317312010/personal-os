# Web 历史文件与恢复边界

更新：2026-10-30（Asia/Shanghai）。

## 当前可用能力

网页底部“导出个人历史”打开 `/history-export`，用户再次点击下载后生成明文
JSON。手机与桌面的编译页面已实测下载，并与网关保存的事件逐项比较。
导出不调用 AI、不写历史，只读取 `history` 命名空间。连接配置、API key、
CLI 登录文件和安装密钥不会被打包；用户自己写入资料中的文字原样保留。

源码已接入文件选择、只读预检、显式确认和空白网关恢复。当前候选正在等待
编译页面验收，最后固定部署包的版本与验证记录以 [Web 状态](WEB_STATUS.md) 为准。
完整服务器恢复仍使用私有双卷备份。

## 格式 v1

顶层严格包含四个字段，不允许连接或登录等额外字段：

| 字段 | 约定 |
| --- | --- |
| `format` | 固定 `personal-os.web-history.v1` |
| `exported_at` | 网关生成的 UTC 时间，含三位毫秒，例如 `2026-10-30T00:00:00.000Z` |
| `source_revision` | 源网关历史修订号，非负安全整数；仅作来源信息，不能当成目标网关的并发令牌 |
| `events` | 按保存顺序排列的完整事件数组，保留事件 ID、原文、版本与引用 |

导出没有加密、签名或内容摘要。预检通过表示格式与当前 reducer 兼容，不能
证明文件未被他人修改、观测内容真实或用户已授权其中的行动。

## 只读预检

预检不使用存储、账号或 AI 依赖。逐个使用 `EventEnvelopeJsonCodec` 严格解码，
拒绝 D4、未知事件版本或信封字段；相同内容的重复 ID 也拒绝，不做去重修复。
按原顺序通过 `reduceCore` 重放，要求每个事件都被应用，拒绝不支持的事件、
非法状态变化和版本冲突。不会排序、补造父事件、改变原文或跳过坏事件。

返回不可变的事件列表和重放投影。错误只返回固定原因码与可选的事件位置，
不附带原始文本、事件 ID 或底层异常。空历史可以预检通过，不创建会话。

恢复保存原始事件 JSON，包括可选空字段及字段顺序。后续常规追加也保留该
前缀，不重新编码旧信封，避免合法文件恢复后被网关误判为修改历史。

限制为 32 MB UTF-8 输入、最多 20,000 个事件，事件数组紧凑编码不超过
7,999,000 字节，为网关现有 8 MB 请求上限预留包装空间。较大的美化导出可能
被拒绝，失败只影响预检。当前重放沿用核心已有规则，不宣称验证了所有业务
载荷、跨对象引用的语义或授权政策。

## 恢复流程与验收判据

1. 在空白网关自动创建会话之前提供文件选择入口；不能先写入新会话再判断空白。
2. 本地预检与摘要预览后，由用户显式确认；预检阶段不发送导入内容或调用 AI。
3. 提交时重新检查目标历史为空、目标修订号一致，复用历史写锁与同源/CSRF 边界。
   有个人历史、过期标签页、并发写入或异常文件时拒绝操作，保留原数据。
4. 写入保持事件内容、顺序和引用，以目标网关自己的修订号管理并发，不恢复账号
   或安装密钥。失败不得发布半份历史；恢复后旧标签页不能覆盖新历史。
5. 从新网关重载实际两轮 fixture，比较目标、计划、反馈、复盘、精确版本及后续
   追加；异常导入验证原数据未变。涉及未完成自动请求时需显式确认，不能在恢复
   完成后直接触发真实 AI 推理。

这些流程已在候选代码中实现；完整编译页面验收仍在排队，不能据此声称已在 OCI
或真实个人历史上完成恢复。浏览器使用核心事件解码和重放；网关独立检查同源、
CSRF、大小、事件 ID、D4、空白历史及修订号，并复用历史写锁。网关没有另写一套
Dart 核心 reducer，校验正常文件的客户端行为与常规追加一致。

## 使用入口

1. 在原网关下载历史 JSON，并保留文件。
2. 启动使用全新资料卷的网关，首次进入页面时不要先创建新记录。选择历史文件，
   检查事件数、对象数、导出时间和源修订号，然后点击“确认恢复到空白网关”。
3. 看到“历史已恢复”后，历史已经写入，但应用还未接续自动请求。确认 AI 额度提示
   后进入应用；AI 连接或登录需要在新网关另行设置。
4. 已有历史的网关可从页脚或 `/?restore=history` 查看恢复边界，但不能覆盖原数据。
   取消或校验失败可以重新选择；提交后若未能确认结果，应先重新打开核对，不自动重试。
