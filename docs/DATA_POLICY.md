# 数据分类与处理规则（草案）

状态：M0 候选规则，尚未映射到具体技术实现。

## 1. 分类

| 等级 | 含义 | 示例 | 默认处理 |
|---|---|---|---|
| D0 公开 | 可安全公开且不指向私人身份 | 项目公开原则、通用术语 | 可进入普通项目文档 |
| D1 内部 | 非敏感的个人配置或项目运行信息 | 功能偏好、抽象目标、任务状态 | 私有存储；按需提供给相关模块 |
| D2 私密 | 能描述个人生活、偏好、关系或连续行为 | 日程、消费偏好、关系复盘、长期日志 | 默认不共享；用途限定；支持修订和删除 |
| D3 高敏感 | 泄露可能造成明显伤害或不可逆影响 | 原始照片、身体与健康数据、私密聊天、精确位置、财务明细 | 最小采集；优先短期处理；严格授权与审计 |
| D4 秘密 | 可直接取得账户或系统控制权 | 密码、验证码、API key、私钥、恢复码 | 禁止进入 Personal OS 内容和模型上下文 |

## 2. 数据状态

数据敏感度与信息可信度是两条独立轴：

- 来源类型：用户陈述 / 设备观察 / 外部来源 / 模型推断；
- 可信状态：待确认 / 已确认 / 有争议 / 已过期 / 已撤销；
- 时间语义：发生时间、记录时间、有效期和复核时间；
- 使用范围：允许访问的领域、Agent 和动作；
- 生命周期：临时、阶段性、长期保留或禁止持久化。

## 3. 最小处理规则

1. 收集前说明目的，不因“以后可能有用”扩大采集；
2. 原始材料与派生结论分开管理；删除原始材料不应暗中保留完整副本；
3. 模型推断不得覆盖用户确认事实，只能形成带来源的新版本；
4. 旧结论应过期或降权，而不是永久定义用户；
5. 跨领域使用 D2/D3 数据必须有明确必要性和权限；
6. 对外发送、公开、购买、预约、关系沟通等行动必须有动作级授权；
7. D4 数据不写入仓库、聊天长期记忆、日志或训练材料。

## 4. 外形模块特别规则

- 原始人像默认为 D3；
- 对人像的结构化观察和审美偏好通常为 D2，涉及健康判断时提升为 D3；
- 不从照片推断无关的敏感属性；
- 不保存可识别第三方的人像或私人资料；
- 用于阶段对比的照片必须标明日期、条件差异和用户授权范围；
- 任何“缺陷”表述必须区分可观察特征、主观偏好与医学判断。

## 5. 待决策

- 原始照片的默认保留时长；
- 云端模型处理是否允许，以及授权粒度；
- 删除是立即物理删除、加密擦除，还是受备份周期约束；
- 长期记忆的过期、冲突合并和撤销传播规则。
