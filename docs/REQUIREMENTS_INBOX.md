# 需求提炼清单

本文件用于把聊天内容转化为可追踪需求。当前条目是提炼框架，不代表需求已经冻结。

## 2026-08-17“男士外貌分析”待提炼

- 用户最初提出的问题与期望结果；
- 输入材料：照片、文字、身体数据、偏好与限制；
- 系统如何分析面部、发型、护肤、体态、身材、穿搭和整体气质；
- 哪些结论被用户接受、否定或要求进一步验证；
- 建议是否有优先级、成本、周期、风险和可逆性；
- 建议如何转换为任务、记录和复盘；
- 哪些信息应成为长期档案，哪些只应临时使用；
- 哪些判断涉及医学、审美偏差、隐私或敏感属性风险；
- 该流程如何复用到健身、饮食和社交模块；
- 用户认为现有聊天体验最缺少什么。

## 待决策问题

1. 首个 MVP 是否以外形优化为纵向入口？
2. 第一版更重视“分析质量”还是“行动与复盘闭环”？
3. 哪些数据必须 local-first，哪些允许进入云端模型？
4. 系统应如何衡量建议有效：客观指标、主观评分、第三方反馈，还是组合方式？
5. 长期记忆的默认保留、过期、冲突与删除规则是什么？
6. 多 Agent 在需求分析阶段承担哪些角色，何时才进入并行开发？
