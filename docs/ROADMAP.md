# 发展路线与里程碑

## 总体路径

项目沿着“先验证决策闭环，再扩充领域，最后形成平台”的路线发展：

1. 需求证据化
2. 单领域闭环验证
3. 多领域协同
4. Personal OS 平台化
5. 可选的产品化与商业化

## M0：项目基线与需求展开

目标：把已有聊天中的隐性需求转化为可讨论、可追踪的产品需求。

交付物：

- 项目使命、边界、术语与非目标；
- 2026-08-17“男士外貌分析”对话的场景、痛点、输入、决策、行动与反馈链；
- 首批四个领域的用户旅程与需求池；
- 隐私、安全、伦理和数据权属约束；
- 需求优先级与待验证假设。

退出条件：核心需求不存在重大歧义；每条高优先级需求都有来源、价值说明和初步验收方式。

## M1：需求冻结与 MVP 定义

目标：选择一个最小但完整的纵向闭环。

建议首个候选闭环：以“外形优化”为入口，完成档案建立、目标设定、方案生成、行动跟踪、阶段复盘的完整链路，并验证它能否复用到健身、饮食和社交领域。

交付物：

- MVP 范围和明确的非范围；
- 功能需求、非功能需求与验收标准；
- 核心对象和数据生命周期；
- 风险清单、人工确认点与失败降级策略；
- 需求基线版本 `v0.1`。

退出条件：可以仅依据需求文档完成验收；新增想法进入 backlog，不再无控制地改变 MVP。

## M2：技术选型与总体架构

目标：在稳定需求驱动下选择实现方案。

交付物：

- 客户端、后端、本地/云端、数据库、模型与 Agent 编排的技术决策记录；
- Personal Data Model、Event/Observation Model、Goal/Plan/Task Model；
- 隐私分级、权限模型、加密、备份、导入导出与删除机制；
- 模块边界、接口契约、可观测性和测试策略；
- 成本、延迟、离线能力与供应商锁定评估。

退出条件：关键架构决策可追溯到需求；不存在因为个人偏好而提前锁定的技术。

## M3：单领域 MVP

目标：完成可供本人长期 dogfooding 的真实产品闭环。

核心能力：

- 个人档案与时间序列状态；
- 目标、约束、优先级和计划；
- 建议的证据、置信度和解释；
- 任务执行、提醒、记录与复盘；
- 用户纠错、建议拒绝和记忆修订；
- 基础数据导出、删除与审计记录。

退出条件：连续使用一个完整周期，系统能基于反馈产生可验证的改进，而不只是重复生成文本。

## M4：多领域协同

目标：让健身、饮食、外形和社交不再是孤立模块。

重点：

- 共享目标与约束；
- 冲突检测，例如时间、预算、恢复与形象目标冲突；
- 跨域因果假设与实验；
- 统一周/月复盘；
- 领域 Agent 与总控 Agent 的职责边界。

退出条件：跨域协调带来的决策质量明显高于四个独立工具。

## M5：Personal OS 平台化

目标：形成可扩展的个人决策基础设施。

扩展方向：金融投资、职业资本、时间配置、消费决策、城市与区位优势，以及新的第三方数据源和执行工具。

平台能力：领域插件协议、统一权限与审计、数据血缘、长期记忆治理、仿真与情景分析、可迁移的用户模型。

退出条件：新增领域主要通过稳定接口接入，无需重写核心系统。

## M6：产品化与商业化（可选）

目标：从单用户系统演进到对其他用户安全有效的产品。

前置条件：多用户隔离、合规评估、安全审计、模型风险治理、可解释的授权与撤销机制、数据迁移能力，以及真实用户研究。不得把本人 dogfooding 的偏好直接当作普遍需求。
