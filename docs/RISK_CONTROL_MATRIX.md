# 风险与人工确认矩阵

状态：M0 产品规则草案。它描述系统行为，不对应具体权限框架或实现。

## 1. 风险由四个维度共同决定

- **影响**：错误会造成多大身体、财务、关系、隐私或声誉损害；
- **可逆性**：结果是否容易撤销或恢复；
- **外部性**：是否会影响第三方、对外发送或改变外部系统；
- **不确定性**：依据质量、模型置信度和未知项是否足以支持行动。

数据敏感等级 D0–D4 只描述数据风险，不能代替行动风险评估。

## 2. 行动风险等级

| 等级 | 典型情况 | 系统允许行为 | 人工控制 |
|---|---|---|---|
| R0 信息 | 查看公开原则、整理已有记录、低影响解释 | 可直接执行和展示 | 不需额外确认 |
| R1 低风险可逆 | 生成草案、调整私人任务排序、建议低成本实验 | 可建议或在已授权范围内修改 | 用户可事后撤销/纠错 |
| R2 中等风险 | 使用 D2/D3 数据生成个性化方案、改变正在执行的计划 | 先解释依据、风险、替代与影响 | 执行或持久化前明确确认 |
| R3 高风险/外部影响 | 发送信息、公开内容、购买、预约、重大训练/饮食改变 | 只能准备草案或方案 | 动作级确认；必要时二次复核 |
| R4 禁止或专业升级 | 医疗诊断、危险训练、胁迫操纵、违法行为、秘密凭据处理 | 拒绝执行；提供安全替代或专业升级建议 | 用户确认也不能越过硬边界 |

## 3. 领域控制矩阵

| 场景 | 风险 | 默认行为 | 升级/停止条件 |
|---|---:|---|---|
| 根据用户确认偏好调整私人建议排序 | R1 | 记录修改理由，可撤销 | 涉及 D3 或跨领域扩大用途时升至 R2 |
| 分析原始人像并生成外形观察 | R2 | 说明用途、质量限制和保留策略 | 健康诊断、敏感属性推断进入 R4 |
| 制定一般训练或饮食计划 | R1–R2 | 结合约束、给停止条件 | 疼痛、受伤、疾病、药物、进食障碍信号进入 R4 |
| 自动调整下一周期任务 | R1–R2 | 只在既有目标与授权范围内 | 显著增加强度、成本或风险时重新确认 |
| 使用其他领域的 D2/D3 数据 | R2 | 说明必要性和目标领域 | 无权限、用途不相容或第三方数据则停止 |
| 生成社交消息草案 | R1 | 仅生成草案，不发送 | 欺骗、冒充、骚扰或胁迫进入 R4 |
| 发送消息、发布内容、预约或购买 | R3 | 展示最终内容、对象、成本和后果 | 未获动作级授权则不得执行 |
| 删除、公开或改变数据访问权限 | R3 | 展示精确对象与影响 | 需要即时明确确认和结果核验 |
| 保存密码、验证码、密钥 | R4 | 拒绝进入系统内容 | 引导使用专用秘密管理方式 |

## 4. 确认必须包含

有效确认至少让用户知道：

- 将执行什么动作；
- 使用哪些数据；
- 影响哪个对象、账户或第三方；
- 是否可逆，以及如何撤销；
- 主要风险、成本和未知项；
- 授权是单次、有限周期还是长期规则。

沉默、历史同意或对另一个用途的授权不能自动扩展为当前授权。

## 5. 自动化边界

允许自动化：整理、计算、比较、生成候选方案、维护私人低风险任务、在授权范围内汇总反馈。

默认禁止自动化：扩大敏感数据用途、公开信息、代表用户与第三方沟通、购买、预约、删除、改变权限、进行医学判断或采用不可逆干预。

## 6. 待验证

- R1/R2 之间应以何种具体阈值区分；
- 哪些计划调整可获得有限周期授权；
- 撤销授权后对历史派生数据如何传播；
- 专业升级提示如何避免过度打断正常使用；
- 用户是否需要为不同领域设置独立风险偏好。
