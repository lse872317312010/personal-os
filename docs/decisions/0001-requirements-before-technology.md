# 0001 — 需求先于技术

- 状态：accepted
- 日期：2026-08-20
- 范围：M0–M1

## 背景

Personal OS 是长期、多领域系统。客户端框架、语言、数据库、模型和 Agent 编排方式都会受到数据边界、离线要求、交互模式、成本和 MVP 范围影响。当前需求尚未稳定。

## 决定

在需求基线冻结并形成验收标准之前，不锁定 Flutter、Rust、数据库、模型供应商或总体技术架构。

允许进行不产生承诺的可行性研究，但研究结论必须回到需求、约束和验证指标，不能以个人技术偏好代替产品判断。

## 理由

- 避免解决方案反向塑造尚未理解的问题；
- 避免早期实现造成路径依赖；
- 让隐私、可迁移性和长期维护成本进入真实权衡；
- 为未来多 Agent 并行开发提供稳定契约。

## 影响

- M0 交付物以需求、场景、数据和风险为主；
- M1 完成范围冻结和验收标准；
- M2 才开展正式技术选型与总体架构；
- 当前代码提交不应建立未经批准的产品骨架。
