# 0017 — 自动 Agent 接入与本机 Web 闭环

日期：2026-10-01

状态：Accepted，依据用户明确要求自动交互，替代决策 0016 中先优化复制和粘贴的交付顺序。

## 决定

日常流程不要求用户复制提示词、粘贴回复或导入协议 JSON。应用自动发送结构化目标、现状及相关历史，接收行动计划；用户记录结果后自动复盘，接受复盘后自动提出下一轮。用户仍负责接受建议、实际执行和报告结果。

先交付单页本机 Web 应用和包含 Node 的 Windows/Linux 启动包。行动卡位于首屏，目标、连接设置和历史按需展开。公开 GitHub Pages 提供下载入口，本机 loopback 服务负责授权回调、模型调用和加密事件存储。

ChatGPT 使用官方系统浏览器 OAuth、PKCE、签名身份验证及订阅使用权限；不读取现有浏览器会话。另提供 Responses、Chat Completions 和 HTTP Agent 适配，厂商更换不改变策略协议或历史对象。凭据仅由本机服务持有，浏览器不保存 OAuth token 或 API key。

本机事件历史经过现有 reducer 校验并按版本追加。Windows 凭据和事件使用 DPAPI；Unix 使用 AES-256-GCM 和仅当前账号可读的本机安装密钥。该存储独立于 Android SQLCipher Vault，未实现两端同步，也不取代 Redmi 真机和真实两轮使用验收。

## 验证

- 测试真实 loopback HTTP、授权状态、PKCE、签名与权限、串行 token 刷新和中断流拒绝；
- Flutter/Chrome 覆盖计划、用户执行和结果、自动复盘、用户确认及自动下一轮；
- 验证重启后的事件恢复、旧回复取消和重复请求抑制；
- 用实际构建页面验证窄屏启动，字体和渲染组件随包加载；
- 自动化测试中的模型回复仅为替身，真实 GPT 推理必须以实际账号授权后的请求验收。
