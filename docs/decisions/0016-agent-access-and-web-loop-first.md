# 0016 — 优先通用 Agent 接入与 Web 闭环展示

日期：2026-09-30

状态：Accepted，依据用户明确的优先级调整。

## 决定

Personal OS 的能力来自用户选择的外部 Agent，包括当前用于开发项目的 GPT。
应用的增量价值是可维护的结构化个人数据、策略、执行、结果和复盘历史，
并让任意能够接收文本和返回协议结果的 Agent 延续这些历史。

当前交付顺序调整为：

1. 打通目标与个人条件录入、上下文交接、建议导入、用户确认、执行、结果、复盘和下一轮策略；
2. 在 Web 展示并验证整套可操作流程，包括更换 Agent 后接续同一目标；
3. 先改善复制、粘贴、分享、阶段提示和格式修正的便利性；
4. 在共享 Application API 上逐步补充 MCP 等在线适配；
5. 对最终 Android 候选版本完成 Redmi G3 和真实两轮 G4 验证。

不要求用户先完成真机验收或配置在线 MCP，才能查看和操作 Web 演示。
Web 演示仍使用页面内存和演示资料，刷新会清空；它不是个人数据的生产存储端。
Android Vault 的权威存储、加密和最终设备验收条件继续适用。

## 验证

Web 必须能通过同一 Application API 完成两轮流程，并证明：

- 个人条件和约束进入实际发给 Agent 的上下文；
- Agent 只创建建议，接受和真实执行由用户单独操作；
- 第二个 Agent 可以看到第一轮执行、结果及用户接受的复盘；
- Strategy v2 引用已复盘的 Strategy v1，第二轮拥有独立的执行和结果；
- 已有历史超过一个查询页时，不静默丢弃后续页；
- 演示回复和自动化测试不计为真实效果或 Redmi 验收证据。
