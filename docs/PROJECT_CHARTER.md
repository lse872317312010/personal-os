# 项目章程

## 1. 项目使命

Personal OS 是一个 Android-first、Agent-agnostic 的个人策略资产与反馈闭环系统。

系统保存个人已有资产、当前状态、目标、约束、历史策略、执行记录、确定性结果和主观反馈。Codex 或其他外部 Agent/Harness 通过标准接口读取这些上下文，负责分析、推理、提出策略、生成计划和完成复盘；Android App 不内置特定模型，也不自行构造推理结论。

Personal OS 的长期价值来自连续闭环：

个人资产与状态 → 目标与约束 → Agent 候选策略 → 用户接受的计划 → App 监督执行 → 结果与反馈 → Agent 复盘 → 策略新版本。

首位用户是项目创建者本人。先验证真实个人问题中的持续收益，再决定是否产品化。

## 2. 核心命题

通用聊天助手可以生成一次性建议，但通常缺少：

- 用户拥有、可纠错、可导出且不依赖模型厂商的长期个人资产；
- 目标、约束、策略、执行和结果之间的稳定引用；
- 对建议是否实际执行、是否有效的连续记录；
- 事实、主观反馈、Agent 推断和建议之间的严格区分；
- 更换 Agent 或 Harness 后继续使用同一历史的能力；
- 把真实实验结果迁移到下一轮策略的机制。

项目验证的核心命题是：

**独立于模型厂商的个人数据与策略账本，能否让可替换 Agent 在连续实验中产生比孤立对话更可执行、更可验证、可持续改进的策略。**

## 3. 产品职责

Personal OS 负责：

1. 保存个人资产、状态、目标和约束；
2. 保存策略、计划、任务、执行、结果和复盘历史；
3. 通过 Android App 监督实施并降低反馈记录成本；
4. 维护时间、来源、版本、可信状态和引用关系；
5. 为外部 Agent 提供稳定的 MCP 和可移植文件接口；
6. 接受 Agent 对资产、策略和复盘的结构化写回；
7. 保证任何 Agent 都不能绕过领域规则直接篡改历史；
8. 支持导出、备份、恢复、修订和删除。

Personal OS 不负责：

- 在 Android App 内运行或封装特定大模型；
- 自行构造 Agent、Prompt Harness 或模型推理循环；
- 把某个模型供应商作为系统权威；
- 第一阶段的多 Agent 编排、自动模型选择或高级披露优化。

## 4. 当前范围

MVP 只保留 Android，首个纵向领域采用外形优化或健身中的一个真实目标。

外部推理可以来自 Codex、Claude、Letta、自建 Harness 或其他兼容 Agent。MVP 不要求同时支持所有客户端，但内部协议不得绑定某个厂商。

后续候选领域包括饮食、社交、职业、金融、时间配置、消费和区位选择。

## 5. 成功标准

MVP 至少完成两轮同一目标的策略迭代：

1. 用户在 Android 建立资产、目标和约束；
2. 外部 Agent 通过 MCP 或兼容交换格式读取上下文；
3. Agent 写入结构化策略和有限周期计划；
4. 用户在 App 中接受、修改并执行；
5. App 保存完成、跳过、偏离、主观反馈和确定性结果；
6. Agent 根据第一轮历史生成复盘和策略新版本；
7. 系统展示策略为何变化及其证据；
8. 更换 Agent 后仍能读取并延续同一历史；
9. 全部权威数据可导出、备份和恢复。

## 6. 治理方式

- README：项目入口、当前状态和近期目标；
- PROJECT_CHARTER：长期使命与产品边界；
- MVP_SCOPE：当前冻结范围；
- REQUIREMENTS：功能与非功能需求；
- USE_CASES：端到端交互；
- ACCEPTANCE_CRITERIA：MVP 验收；
- ROADMAP：阶段计划；
- architecture/：实现边界与协议；
- decisions/：重大决策记录；
- CHANGELOG：基线实质变化；
- GitHub Issues：独立的验证与执行事项。

## 7. 当前决策

截至 2026-09-15：

- MVP 只保留 Android；
- Android 是个人资产、策略历史和反馈结果的权威端；
- App 不直接接入特定模型；
- 推理元交互完全交给外部 Agent/Harness；
- MCP 是首选 Agent 数据与工具接口；
- JSON/JSONL Bundle 是必须保留的兼容与退出接口；
- Windows客户端、多设备同步、内置模型和高级披露策略暂缓。
