# 项目章程

## 1. 项目使命

Personal OS 的使命是把分散的个人信息、目标、约束和反馈组织成长期可演进的决策系统，帮助用户在真实生活中持续完成“理解现状—选择行动—执行—复盘—校准”。

首位用户是项目创建者本人。当前以解决真实个人问题和验证闭环为先，未来是否产品化不影响当前需求判断。

## 2. 核心问题

通用聊天助手能提供一次性分析，但通常缺少：

- 稳定且可纠错的长期个人状态；
- 对目标、约束和冲突的统一管理；
- 从建议到任务、记录和复盘的连续链路；
- 事实、推断、偏好、建议与不确定性的严格区分；
- 对建议有效性的长期验证；
- 用户可理解、可撤销、可导出和可删除的数据治理。

本项目验证的核心命题是：**跨时间、跨领域的决策闭环能否比孤立对话产生更高的实际价值。**

## 3. 当前范围

首批领域：

1. 健身与身体状态；
2. 饮食与营养；
3. 外形优化，包括护肤、发型、穿搭、体态与整体形象；
4. 社交与关系优化。

后续候选领域包括金融投资、职业资本、时间配置、消费决策以及城市与区位选择，当前不进入实现范围。

## 4. 当前阶段目标

M0 阶段只做问题定义与需求证据化：

- 将既有对话转成可追溯需求；
- 明确术语、角色、场景和决策闭环；
- 标记已确认事实、工作假设和待决策问题；
- 给每条高优先级需求定义可观察的验收方式；
- 明确数据敏感度、风险和人工确认点；
- 为 MVP 选择提供依据。

## 5. 成功标准

M0 完成必须同时满足：

- 每项核心需求能追溯到用户陈述、实际行为或明确假设；
- 需求没有依赖某个预设技术方案才能成立；
- 至少形成一个端到端候选闭环；
- 高敏感数据的处理边界明确；
- 重大未知项被显式记录，没有被伪装成结论；
- 用户可以据此决定进入 M1、补充证据或调整范围。

## 6. 治理方式

- `README` 负责项目入口和当前状态；
- `ROADMAP` 负责阶段、交付物和退出条件；
- `REQUIREMENTS` 负责候选需求及其证据等级；
- `REQUIREMENTS_INBOX` 接收尚未结构化的材料；
- `decisions/` 保存重要决策及其理由；
- GitHub Issues 承载需要讨论、验证或执行的独立工作项；
- `CHANGELOG` 记录项目基线发生的实质变化。
